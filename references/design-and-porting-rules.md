# 审阅面的设计规则与改造规则

## 〇、先看这一节：五条生成规则

下面四十多条都是**实例**。真正要记的是这五条 —— 每一条都能生成一大片具体规则，
而**遇到新问题时，先在生成规则的层面改，不要在症状那一处堵**。

### 一、**一处事实，只能有一个来源。**
不留副本、不留兼容层、不留"以防万一"；镜像的东西要有闸门核对；跨副本取最新**并出声**；
同一个常量/文件名/编号逻辑不许两处定义。
> 实例：跨副本漂移（陈旧那份静静获胜）、契约副本、`STORYBOARD_FILE` 两处、轮次编号两处、镜像常量闸门。

### 二、**信息跨过任何一条边界，都必须还是同一件事。**
两个基准要分清；占位符的**语法**要定死；幂等键取**身份**不取内容；告警要**进数据**；
说得不许比知道的多、也不许把成功说成失败；schema / 校验器 / 宿主 / 桥对同一字段**只有一种含义**。
> 实例：信封、唤醒语、`watch` 三种读法、注入点三种写法、`capabilities` 两种含义、告警只给人不给机器。
> **今天十几次同族问题，绝大多数是这一条的违反** —— 每一条边界都是一次翻译，而翻译会悄悄丢东西。

### 三、**凡是"需要它的时候它必须在"的东西，都不许挂在会失败的那个条件上。**
刷新出口不许藏在告警里（因为"页面变了"不产生告警）；提示里要求人做的动作，页面上必须做得到；
粒度入口不许只给一种；本机草稿的恢复不许依赖时间轴读得到。
> 实例：没有重载按钮 / 按钮长在告警里、提示叫人做做不到的事、草稿只在时间轴读到才恢复。

### 四、**人的决定只能由人给出，而且改完即结束。**
预置值只能来自产出方，且必须区分"默认"与"人选"；上一轮的文字**不预填**；
不许要人清理才算确认；页面**少存状态**（存了就会与文件里的那份打架）。
> 实例：默认通过伪造人的决定、图片决定被生成器猜测覆盖、"要清空反馈才能通过"。

### 五、**验收必须能被证伪。**
关键断言用**深度相等**；必须有一个**会失败的对照组**；用桩替掉的那一环**必须写明**；
**数字本身**也要被验（异步断言要 await）；判定机制要用**行为把参数逼出来**；**观察 ≠ 机制**；**写清验的是哪条链**。
> 实例：桩比宿主更正确、假绿 `seq`、harness 不 await、"围栏不等于门后"、`pgrep` 匹配到自己。

### 怎么用（**最小改动**）
1. 拿到一个具体问题，先问：**这违反的是上面哪一条？**
2. **在那一条的层面改** —— 改规则、改契约、改一处实现，而不是把症状按下去。
3. **改动越小越好。** 如果同一类问题要在十处分别堵，说明**抽象找错了**（回到第 1 步）。
4. 改完补一条**能区分新旧行为**的回归（旧代码在这条上必须红），并把**产生它的那件事**写在规则旁边。

## 0. 缝是什么

**一个面**（`review-surface.json`）＋ **一份桥**（`review-bridge.js`）＋ **一个宿主**。

宿主只做三件事：**把字节搬给页面 / 把提交原样落盘 / 把人叫醒**。别的它一概不解释。
页面与产出方保留**全部语义**：审什么、怎么决定、反馈文件长什么样、批准算不算"门"。

判断一个东西该放哪，问三句：
1. 是**所有审阅面都要懂的**吗？→ 进公共件（契约 / 桥 / 宿主）
2. 只有**某一家**才知道吗？→ 进那一家，**宿主永不解释**
3. 是**宿主能力**吗？→ 进宿主，且**两种宿主必须行为一致**


### R0 缝只替"审阅这条管道"，**不替内容服务**
一个面可以依赖它自己的内容服务（视频项目要项目自己的预览服务才看得到画面；报告面可能要先跑出 HTML）。
**缝只管**：把页面 serve 出去、把资产搬给页面、把提交落盘、把人叫醒。**内容怎么来的，是产出方自己的事。**
（佐证：video-craft 的页面上 `<hyperframes-player>` 指向项目自己的预览服务 —— 那个服务没起、或素材被删，页面就是"路径通但看不到东西"，**这不是缝的故障**。用户 2026-09-26 当场确认过。）

## 一、设计规则（新审阅面怎么写）

### R1 面只声明那几个字段，宿主永不解释
required 7：`contract_version` `id` `title` `project_root` `dir` `entry` `wake`；optional 4：`description` `feedback` `watch` `capabilities`。
**宿主不知道"页"是什么、"章"是什么、"版本"是什么。** 往契约里加的每一个业务字段，都是欠给三个实现的债。
（佐证：video-craft 的逐章 JSONL 与 ppt-hell 的逐页版本，**没有任何一个业务字段**进契约 —— 它们在收件层被翻译。）

### R2 两个基准，别混
- **页面里的资产引用与 `entry`** → 相对 **`dir`**（"被 serve 的那棵树"上的地址）；
- **surface 自己声明的文件（`feedback` / `watch`）** → 相对 **surface 文件**。

**代价**：这条埋过两次雷 —— 校验器曾按 `dir` 解析 `watch`，宿主也曾按 `dir` 解析 → 一个合法面的 watch 被**静默丢弃**（`watching: []`），而面照样"打开成功"。第二家（页面在子目录里）把它暴露出来；第一家因为"两种解析恰好都落在 `dir` 内"而看不见。

### R3 注入点：**裸标记独占一行**
```
{{REVIEW_BRIDGE}}
```
宿主**原地**替换它，换成完整的一段标签（内联源码或外链脚本，由宿主决定）。**放进 `src=""` 里、或放进 `<script>` 里，都会被撑破。**

**代价**：契约原来只写"宿主把它换掉，换成什么由宿主决定"，**没说清标记本身长什么样** → 长出三种互不兼容的页面写法，而每种只在"换一个宿主"时才炸（桥 404 / 嵌套 script / 页面白掉）。现在：校验器拦 `bridge_placeholder_not_bare` 与 `_multiple`，两个宿主都容忍三种写法。

### R4 页面不自带服务器、不放桥的副本、不藏宿主知识
不透明帧里取不到 `/api` 下的 `<script src>`（实测 403），所以桥**只能由宿主注入**。
**代价**：页面里放过桥的副本 → 插件模式下页面地址是**路由**而不是文件路径，相对引用 404；页面还曾硬写 `base:'../'`（现在 0 处宿主知识）。

### R5 状态行只说自己核过的事；**也不许把成功说成失败**
- 宿主"**接受**了" ≠ "**通知到**了" → 页面必须分档说（已进回合 / 已入队 / 未核对）；
- 反过来：同一次提交重发意味着"之前已送达"，页面**不该**说"保存失败"。

**假阳性与假阴性一样是骗人。** 页面要说的始终是"实际发生了什么"。

### R11 **页面必须能刷新自己**（而且入口不许藏在告警里）

页面的 **JS 本身也会变**（改提示文案、改判据、加一条入口…）。而**"页面变了"与"数据变了"是两件事**：
数据没变 → 不会出现任何"陈旧"告警 → **如果刷新入口只嵌在那个告警里，人就永远拿不到新页面**。

**代价**（2026-09-26，用户当场撞上）：用户报「**标签页里没有重新加载的按钮**」，我让他重载拿新页面 ——
而他重载不了；后来那一页确实补了一个「重新加载」按钮，**但它嵌在橙色告警里**，于是"页面 JS 变了、数据没变"
这个场景仍然无解（先有鸡先有蛋：新页面才带那个按钮，而要到新页面就得先刷新）。

**要求**：页面上一处**永久可见**的刷新入口（角落或页脚一个 `⟳` 就够），**且它不依赖任何告警出现**。
（同一批检查：页面里每一句"请你做 X"，页面上都要能真的做 X —— 这是 R11 与那条提示语的同一条根。）

### R5b **只给人看的告警 = 机器看不见的告警**

如果页面知道一件**会影响拿到这份数据的人怎么读它**的事（"这一条是对着旧版本写的"、"这一屏我还没看完"、"这张图是占位"），
那它**必须在数据里**，不能只在屏幕上。

**代价**（2026-09-26，用户当场发现）：video-craft 的陈旧提示**真的出现了**（戳链是通的），页面也把
「**这一条是在时间轴已变的提示下提交的（见上）**」写给了人看 —— 但**记录里没有任何痕迹**。
于是模型收到一条可能是对着旧文字说的话，**却无从知道**。那条提示存在的全部意义
（"人对着旧文字提的意见，会挂着一条已经不存在的话"）**在机器那一侧完全失效**。

**检查方法**：页面上任何一条"警告 / 前提 / 免责"文案，问一句 —— **它该不该影响拿到这条数据的人怎么读它？**
该，就进数据（并在产出方的协议文档里写清它的含义）。

### R6 幂等键取「这一次事件的身份」，**不取「这件事的内容」**
**代价**：唤醒 id 曾从 `(会话, 面, 单位, 文本)` 算 → 页面的"整套提交"每次送**同一句话** → 第二次恒定命中去重 → **静默消失，还报成功**（宿主 `prompt` 命中 requestId 时直接 `return {accepted:true}` 却什么都不入队）。
现在 id 折进**本次提交 payload 的哈希**：新提交必然新身份，同一次提交重发身份不变（重试天然幂等）。

### R7 意见的生命周期：**改完即结束**
人给意见 → 模型改 → **那条意见关闭**，页面回到"未处理"，**一次点击就能批准，不需要人清理任何东西**。

**代价**（用户本人裁定）：我原来定的是"上一轮意见带回来、要清空才算确认"。真人用一次就看穿：*"我给你意见，你改完了，就是结束了，这个意见也不该有了。"* 而且 `resolve` 过的同一句话会**第二次变成待办**（同一条意见的两个症状）。

### R8 框选坐标是**可执行的信息**，不是"用户觉得这里有问题"
**代价**：用户圈了一带 + 五个字「底部没对齐」。按坐标裁出那块（归一化坐标先 × 画布尺寸）就看到了实体缺陷：横轴 280–1700 vs 柱组 420–1500，两端不对称。
**`w > 0.9` 的框选按"整页重做"处理**，不是"某处小修"。

### R9 核验要比 **seq / 身份**，不许"扫日志找同 id"
**代价**：核验从日志**末尾往前扫**找同一个 rpcId → 被去重的那一次找到了**上一次那条旧消息**并报成功（实测 `seq:22 < before:25`）。**假绿的位置恰好就是出事的那一次。**

### R10 **审阅的粒度由产出方决定**，页面不许把逐单位当成唯一入口

有的东西**天然逐单位**（幻灯片的每一页、逐屏文案、逐章画面 —— 改一页是一页）；
有的东西**整体看一遍说一句就够了**（成片、报告、一段剪辑的节奏）。
**两种都要能表达，而且由产出方决定用哪种。**

缝**两种都支持**：`feedback` 只是一份文件，payload 的形状是产出方的 —— 逐单位是一个数组，整体就是一条记录，都不需要改契约。

**代价**（用户 2026-09-26 指出）：video-craft 的视觉审阅页把提交**绑死在"选中的那一屏"**上（`stepId: state.step`，没选屏按钮就 `disabled`），于是"整片看完了说一句"这件事**在页面上无法表达** —— 人只能挑一屏、把整体意见塞进去，或者干脆不说。
用户的原话：*"不是所有的内容都要逐页反馈，这个根据 Skill 来。比如刚才的反馈就不需要逐页提交，整体最后反馈就够了。"*

**检查方法**：拿到一个审阅面，问一句 —— **"我不想针对任何一个单位，只想说一句整体意见"**，页面允许吗？不允许就是缺一条入口。

## 二、改造规则（已有的审阅页怎么接）

**总原则：不改产出方的对外语义。** 形状差异一律在**收件层**翻译。

已核实的"一个字没改"清单（video-craft 那次）：记录字段一个不多、每章一份 JSONL + 只追加 + `.previous/` 备份、`status: open/resolved`、agent 协议文档、页面位置、时间轴位置。

### 四类形状各自的落法

| 形状 | 代表 | 要点 |
|---|---|---|
| 逐单位决定 + 单位级版本 | ppt-hell | 面声明 `watch` 盯快照；页面收到戳后**自己**读快照、自己 diff、**只换变了那几个单位的图** |
| 追加式日志（逐章/逐条） | video-craft | 面声明**一份**提交文件；Skill 收件时翻译成自己的追加 + 备份；**幂等靠记录内容哈希**（不能往记录里加字段 —— 那正好会改掉形状） |
| 只有整体批准 + 备注 | — | 可以上缝（一条记录），**也可以留在对话里** |
| **需要"模型在旁边多轮协商"**（解释、追问、改范围） | — | **不上缝**。缝的表达力是「一页 → 写一份文件 → 醒一次」，**答不了"再解释一遍为什么推荐这个方法"** |
| **看着像审阅、其实是渲染自检**（headless 截图 + DOM 断言，无人下决定） | — | **不上缝** —— 它不是人审 |
| **整体一次 + 可选逐单位**（最常见） | video-craft | 页面必须**两条入口都给**：不选任何单位也能写整体意见；选了单位才是逐单位 |
| 在板子上挑，**结果就是那句话**（"我挑好了，你看着办"） | — | 用 `wake` 交回去；**可以不声明** `feedback` |
| 在板子上挑，**结果是下一步要执行的工件**（如 `selections.json` → 一个消费者脚本） | 要 | **仍声明 `feedback`**（工件走数据通道），`wake` 只当**门铃** |

### 步〇（**开工前先问这一句**）：**这一家要的东西，缝有没有？**

把这家面的需求列一遍再动手：**大媒体要 `Range`/流式** · 要上传替换素材（`capabilities`）· 要本地渲染/预览服务 ·
要鉴权 · 要分页/惰性加载 · 要断线重连……**逐条对着缝比一次**，缺的当场报，别写到一半才发现"够不着"。

> 证据（2026-09-26，第四家 EDL）：它开工后才发现**缝的宿主不支持 `Range`** —— 而这一页的全部工作就是拖着刷时间轴，
> 真素材 **1.77–2.04 GB**，无 Range ⇒ 每次加载拖完整个素材。前三家都不放"大媒体"，所以这条潜伏缺口它们碰不到。
> **补完之后它是第一家"不再自带服务器"的线。** 下一家如果还要流式或本地渲染，**先问缝，再写服务器**。

### 五步

1. 指定一个目录放页面与资产；入口留 **`{{REVIEW_BRIDGE}}` 裸标记**；
2. 写 `review-surface.json`（校验器必须 **0 警告**）；
3. 页面改用桥：`asset / readText / write / wake / on('changed')`；
4. Skill 侧收件：读 `feedback` → 校验 → **决定它算不算"门"**；
5. 没有插件时，用模组的 `serve-review.mjs` 当宿主。

### 改造时要顺手查的三件事（都踩过）

- 页面里有没有**硬写的宿主知识**（base、端口、路径）？
- 页面有没有**自己存一份状态**？存了就会出现"模型改完、页面还挂着"（ppt-hell 踩过；video-craft 因为**页面无状态**而结构性不会犯）。
- 生成页面这一步：旧页可能是**剪贴板时代**的（连不上宿主）→ 按产出方自己的文档从模板重生成；**先记下旧页的哈希再覆盖**（"被取代"，不是"不见了"）。

## 三、缝自己的修正（被第二家逼出来的）

| 修正 | 怎么发现的 |
|---|---|
| `watch` 一律相对 **surface 文件** | 第二家的面在子目录里 |
| 无插件宿主**必须认** `watch`（原来按整棵树摘要） | 同一个字段的第三种读法 |
| `capabilities` = **宿主支持 ∩ 面声明**（"现在真正能用的"） | 两个宿主对同一字段各说一套，且会**广告做不到的事** |
| 桥的**完整性闸门**：缺方法就拒绝内联并指名哪一份、缺什么 | 陈旧副本静默获胜 |
| 解析桥取 **mtime 最新** | 三份运行时副本同时存在 |
| 注入写法容忍三种、规范只一种 | 两种宿主支持不相交的写法 → 死页面 |
| 越界/被跳过的项要**出声**（`warnings`） | 静默跳过让"哑面"看起来正常 |
| 宿主生命周期**只留一份**（模组 `scripts/lib/review_host.py`） | 两家各一份且**已经漂移**（僵尸判据、SIGKILL 升级） |
| **宿主静态分支必须支持 `Range`**（`206` + `Content-Range` + `Accept-Ranges: bytes`；不可满足→`416`） | 第四家带**大媒体**（真素材 1.77 GB），前三家不放媒体所以看不见；无 Range + `no-store` ⇒ **每次加载拖完整个素材**，而这一页的全部工作就是拖着刷时间轴 |
| **MIME 表要覆盖真用到的扩展名**（当时漏了 `.mov`） | 同一族的小潜伏：给 `application/octet-stream` 通常还能播，但那是撞运气 |
| **流程指令与"人的话"不许抢同一个字段**：页面只传 `unit`、**绝不覆盖** `text`；人的话走**数据**（提交文件 + 收据） | 桥允许页面整句覆盖唤醒语，可一覆盖就把面里那句"**先收件、再跑门**"的流程指令挤掉了 —— 一个字段两个来源 |
| **原生记录的落点从"surface 文件所在那一层"推，不许从 `dir` 推** | `feedback` 与 `dir` 都相对 surface 文件，但**可以落在不同层** —— B4 是第一个把它们逼出不同答案的（`dir: ".."`，而 `feedback` 在 surface 那层）；第一版 inbox 按 `dir` 解析，把原生记录写到了**上一层** |
| **默认行为要与命令名一致**：`open` 默认开、`start` 默认不开，各留一个反向开关（`--no-open` / `--open`），并在返回里如实报 `opened` | 两个前端各一套行为（Node 不开、Python 开）——**同一个词在两个入口意思是两回事**，用户和调用方都会被绕进去 |
| "**找模组**"的适配器**留在各家** | 那是"调用方所处地形"的知识，不是模组的 —— 收进去等于让模组知道"谁在找我" |


## 三之二、「只留一份」在跨语言时是什么意思

**"一份"指逻辑一份，不是文件一份。** 跨语言时：

1. **唯一的实现收在"所有调用方本来就已经依赖的那个运行时"里。**
   本缝的底线是 **Node**（契约校验器、无插件宿主、桥都是 Node CLI）—— 所以**生命周期也必须是 Node**
   （`scripts/review-host.mjs`），否则 **Node 技能就被关在门外**（bypage 全是 `.mjs`，而它的运行契约
   **不许假定 `python3` 存在**）。
2. **别的语言只允许放"不带判据"的传输层**（子进程调用 + 解析 + 映射），并要有**可证的薄**
   （AST 审计：非 docstring 语句数）。
3. **判断"该收在哪"的问题不是"谁方便"，而是"谁已经在那儿"。** 收在大家都已依赖的运行时里 ⇒ 谁都不多一个依赖；
   收在别处 ⇒ 另一侧要么加依赖、要么复制一份。

**代价**（2026-09-26，bypage 报上来的）：我上一轮把生命周期"只留一份"地收进了 **Python**，于是
bypage 无路可走 —— 要么依赖 `python3`（违反它自己的契约），要么复制生命周期（正是刚消灭的漂移）。
**这不是它搬错了，是我指定错了容器。**

## 四、验证规则（怎么知道"真的成立了"）

1. **关键断言用深度相等**，不要"某个字段在不在"。宿主套信封的 bug 就是这么漏的。
2. **结论性验收要用对方的真实产物跑**，不要自造 fixture —— **每一侧都测自己，缝就是断的**（第一次真人审阅 30 秒抓到 6 个）。
3. **用桩替掉的那一环必须写明**。B8.5 那次"六条全过"里 `changedSeq` 是**桩**喂的，而**桩比宿主更正确** → 它证明的是"桩能发戳"，不是"宿主能发戳"。**这种结论不许写成"这条链成立"。**
4. **数字本身也要被验**：harness 必须 `await` 每一个异步断言 —— "全绿"是另一种"看起来成功了"（修好之后立刻红了 11 条）。
5. **判定机制时用行为把参数逼出来**：创建/删除那个被 watch 的文件、数 `/api/review.page` 的请求次数。不要只看代码，也不要只信观察。
6. **看起来像装饰的返回字段要当场核**：`watching: []` 当时就在说"我没在盯任何东西"，而没人看它。
7. **迁移永远在删除之后**；"只有一份"这句话要 **grep 可证**（`from X import` 计数为 0）。
8. **既有的红要单独标出来**（环境性失败与本次改动区分开），否则它会被顺手算到下一次改动头上。
9. **对抗性用例**：判据要防"永远为假" —— 拿 A 的状态问 B 必须不认，拿 B 问 B 必须认。

10. **一道对所有请求都同样回答的围栏，证明的是围栏，不是门后的东西。**
    `/api/*` 对**没有 cookie** 的请求一律 401 —— **连从未注册的路径也是 401**。所以
    "七条路由无 cookie 全 401"**只能证明鉴权围栏在，不能证明那七条路由注册了**。
    有效证据是**带 cookie 的对比**：**注册过的** → 200/400；**没注册的** → 404。
    **一般化：验收必须有一个"会失败的对照组"**（negative control）—— 只有"该失败的失败了、
    该成功的成功了"，才说明你测的是那个东西。（同一条道理的另一面：判据要防"永远为真"或"永远为假"。）

11. **"谁写的"要和"谁读的"对得上**：本轮亲测到的反例 —— `package.json` 的 `files` 列了 9 项、
    实物全在、`npm pack` 打出来也对，但**装法**仍然可能与 README 不一致（用户 profile 里
    插件只出现在 `bundles`、不在 `dependencies`，是旧的手改法留下的）。**打包正确 ≠ 装得上。**

12. **"服务端返回 ok" ≠ "页面画出来了"。**
    每个面的验收都要有一格：**加载后断言页面真的长出了内容**（例如 `#beats` 有 N 个子元素、导航有 N 项、进度条在），
    而不是只看宿主/工具返回 `ok`。**反面对照**：把桥或网络换成"**永远不返回**" → 页面**仍须**画出内容。
    > 证据（2026-09-26，用户一张截图）：video-idea 的念稿面在**插件路径**下只显示静态骨架、逐段全空、**零报错** ——
    > 因为 `boot()` 把整个 `render()` 挂在 `await ReviewBridge.connect()` 上，而 `try/catch` 只接得住"拒绝"、
    > 接不住"**一直不返回**"。上一轮的验收只验了 `review_open` 的返回（`bridge_ready: true`），**没验页面**。

13. **"前几家没露出来"不等于"这条链是好的"** —— 只有**换一个形状**才验得出潜伏问题。
    video-idea 是第一家**把渲染挂在握手上**的页面；ppt-hell / bypage 都是"先用内联数据画出来、再接线"，
    所以同一条缝 bug 在它们身上看不见。**这就是第二家、第三家必须真的做的理由。**

14. **"没有覆盖"不是"绿的"。** 有的面在接缝**之前**根本没有测试（例如 video-craft 那条剪辑线：
    `tests/` 17 个文件里，`apply_selection` 只出现在**注释**里，`edl_preview_*` 与 `selections.json`
    的读写**零覆盖**）。这种面的基线要写成 **"无覆盖"**，**不许写成"测试全绿"** ——
    接缝顺带给它的第一张**回归网**，本身就是一项产出。

15. **判据的失败方式也是判据的一部分。**
    一条断言如果**摔掉套件**（未定义、抛异常、作用域写错）而不是**报红**，它就不是闸门。
    报红要带上**原文**（例如 `…sandboxed and lacks allow-same-origin`）。
    **同一处被三家踩了三次**（bypage 2 次、video-idea 1 次）：桩只记 `innerHTML` → 数成 0（"永远为假"）；
    断言写在未初始化的作用域里 → 套件直接摔。**"没报红"和"报红"之间的差别，比绿和红之间还大。**

16. **"假输入"必须在报告里标明。** 改造时经常不得不**造输入**（真内容机械映射进本家契约、
    上游家的真记录喂不进本家的 `review_kind`）。可以造，但**每条输入要标清它是哪一类**：
    【映射的真内容】/【原生真记录】/【夹具·对照副本】，并在结论里写清**你验的是哪条链**。
    > 正例：bypage 的 storyline 面用真 Adidas 架构**机械映射**（20 页真文本、7 章 `audience_shift` 逐字节相同，
    > 只有 `page_type` 与素材候选是推导的，且记了来源路径），并在报告里标明"这是映射、不是原生真记录"。

17. **改造前，先让每一家自己列全它的面，并解释"哪些不是面"。**
    > 证据：我按记忆排的顺序**漏掉了 ppt-hell 的「模板审阅」**（它文档里明说与页面审阅**不要合并**），
    > 是 bypage 交清单时把总数对上才发现的。**"能说清为什么它不是面"与"列出面"同等重要。**

18. **规则越稳，越容易拿"上一个个案"当规则用。**
    四家做完后，第五条形状路线（EDL）**改到了规则本身**（第 4 类形状必须拆成"结果就是那句话"与"结果是工件"两半）——
    而前四家都只是补实例。**每接一家，都要问一句："这是这条规则的一个实例，还是它推翻了这条规则？"**

19. **改造前后跑"同一张行为网"，不要分别写两套判据。**
    把一面现有的行为写成一张网，**同一张网能在"改前"和"改后"两种模式下跑**（例如 `--legacy` / `--seam`）：
    **改前全绿 ＝ 基线真实；改后仍须全绿 ＝ 没把行为改坏。**
    > 证据（2026-09-26，proposal B4 那一面）：这一面此前**零行为覆盖**（17 条断言全是静态取模式，一条都没起过 session），
    > 它先造夹具（按本家契约程序化构造 + 用本家 builder 产 bundle 与页面）再写这张网 —— 于是"上缝"第一次有了可比的基线，
    > 而且红/绿不用靠"退回去改一处"来造。**这比"退一处看它红"更强：它同时证明了"没改坏"。**

20. **"开不了浏览器"不许是致命错误。** 老实现里 `open` 失败会 `fail(...)` 直接终止 —— 上了缝之后，
    宿主如实回 `opened: false` 就继续（`open` 默认开、`--no-open` 关）。**内容与提交都不该依赖"弹出了一个窗口"**：
    无头环境、CI、以及"作者手边没有图形界面"都是常态。

21. **"不是每个面都该上缝"是这套东西的一部分，不是它的失败。**
    检查句（两句，缺一不可）：
    - **"这里有人下决定吗？"** —— 没有，就不是面（装配/取数/校验/渲染自检都属于这类）；
    - **"这个决定需要模型在旁边多轮协商吗？"**（解释、追问、改范围）—— 需要，就**留在对话里**，别用一页静态纸换掉正在进行的对话。

    > **权威依据（用户本人早先的裁定，从 git 历史里挖出来的）**：quanti 的 `Release v0.3.0`（`8c4be05`）
    > **删掉了 CP0 的确认机器**（`confirmation-record.schema.json` 与全部哈希绑定），代之以"报告里一句话确认范围"，
    > 理由写得极准：**"CP0 是人的决定，不是机器的状态；机器能验的只有'某个字符串非空'。"**
    >
    > **同一族的三处别扭**（2026-09-26，quali/quanti 那一路给的）：
    > ① 这两家的决定全在**要求阶段、模型就在旁边**，不在产物阶段；
    > ② "改方案/换范围"是**开放文本回流**，不是决定词表 —— 硬接就得把 `corpus-profile.md` 的单一真相源**复制一份**到 feedback 文件（违反生成规则一与 R7）；
    > ③ **粒度对不上**：报告按章节叙事排序、findings 按 ID 排序，硬要问"只想说一句整体意见"就得**凭空发明一个跨两个编号空间的单位**。

22. **"看着像审阅"要验到最后一步**：一个面在接缝前先问 —— **它的产物里有没有任何一条"人下的决定"？**
    > 反例（quali 的 `review_report.mjs` / quanti 的 `visual_smoke.mjs`）：headless Playwright 截桌面 / 390 / PDF
    > + DOM 断言（元素在不在、有没有外链、有没有横向溢出）—— **全程无人下决定**，那是**渲染自检**，不是人审。
    > 另一类：quanti 的**分类审计**有词表（`passed|exploratory|failed`）但**没有人工决定字段**，缺了只是降级成 `exploratory` —— **降级规则不是决定入口**。

23. **"从未运行过的分支"是最容易藏 bug 的地方** —— 它比"没有测试"更隐蔽：**代码在、覆盖也登记着，只是那一支从来没被执行过。**
    问法很直接：**"这条链的最后一公里，有没有任何一次真的跑到过？"**
    > 证据（2026-09-26，ppt-hell 模板审阅面）：发布闸门的「**全通过 → 放行 → 打包**」整条链
    > **从未被任何测试执行过**（原有的模板侧用例全在验"起服务器/判死活"，而磁盘上唯一的真项目走的是库模板路径、
    > 到闸门前就被拒）。**而这一片恰恰是刚发现"只认旧写者/只认旧来源"两个真 bug 的地方** ✗。
    > 补法：**用夹具把那一支跑到**（并把闸门要的几样都造齐），**在测试里标明这是夹具层**；
    > 结论那一层仍只有真项目才算数。**跑不到就说跑不到。**

24. **"扫描式判据"（这种东西不许出现）要过三关**，否则它多半"永远为真"：
    - **范围 ≥ 标志物可能出现的地方。** 只扫提名目录会漏掉**新目录**。
      > 证据：一份 `review-surface.json` 放进新建的 `review/` 里，第一版扫描**整个漏掉** —— 而"漏掉"是这类判据最坏的失败方式。改成扫整棵树后，**同一次植入从 1 处红变成 3 处红**。
    - **自指与假阳性。** 跳过断言自身；**"公共件登记表里有这个名字" ≠ "这一家用了它"**（给窄豁免 + 写明理由）；与主题无关的命中（例如报告页里的 `localStorage`）**降级成软提示并照实数报**，不计入红。
    - **用真植入反向验它。** 把标志物写进一份**文档的正文段落**，它**必须红**。
    - **正向也要验：拿"已经查实确实存在过"的清单当判据。** 它比"靠自己回忆列词表"可靠 —— 而且**它会抓到你自己没想到的漏**。
      > 证据（2026-09-26，去标识化那一路）：判据换成"审计已查实的那四条命中清单"后，**当场抓到第一轮漏掉的 2 处**
      > （`2023增长乏力` / `KPI市场份额下滑` —— 审计报告只用中文点过名，没进任何词表）。
      > **判据能在它自己的作者身上找到漏，才说明它不是事后追认。**
      > 证据：写进 `SKILL.md` 正文 → 两边都红；于是最终豁免只窄到"**登记这条回归自己的那一行**"（否则连"这条回归在拦什么"都写不出来）。
    - 附带一条：**指纹要用相对路径、口径固定**，否则不可对照。
      > 证据：一次基线指纹**含绝对路径**，与后来的相对路径口径**无法直接比对**，只能改用 `git diff` 原文当证据。

25. **红/绿对照必须用"**冻结的改前真身**"，不能用"同一个生成器的另一种调用方式"。** 否则红/绿是假的。
    > 证据（2026-09-26，proposal B4）：改前的 **56 个文件被冻结**在 `.scratch/proposal-seam/legacy/`，
    > 附 `frozen-hashes.json` 并**事后自检 0 个不一致**；`--legacy` 跑的是那份真身，
    > 于是"新判据组在 legacy 上 17 条里 13 条红"才是真红。

26. **测试必须能"连着跑两次"** —— 第二次跑出来的红，多半是**夹具自己漏了状态**，不是产品坏了。
    "干净环境下第一次跑全绿"**不算绿**：那只是它没被人连跑过。
    > 证据（2026-09-26，插件那一路）：它报 `63/63`；我**自己跑第二遍**得 `62/63`，失败在它自己造的软链上 ——
    > `EEXIST: symlink outside-target.png -> surface/uploads/link.png`（上一轮留下的软链没清）。
    > 同一天早些时候，EDL 那条线的"偶发"也是同一族（**每个用例各起一次浏览器、失败路径不关** →
    > 漏出来的进程攒成"偶发"）。**"偶发"和"第二次才红"，绝大多数都是漏出来的状态。**
    > 验收写法：**连着跑两次（或三次）**，并把它作为判据的一部分。

27. **"同步 / 发布"类操作：提交前必须断言「实际进入的文件集 == 我预期的文件集」，出现预期外路径就停下问人。**
    "把整个目录整体拷过去"这种实现**会把你没看过的东西一起发布出去** ✗ —— 尤其是**别人正在同一个目录里写的在飞产物**。
    > 证据（2026-09-26）：一个 agent 只想改 `GOTCHAS.md` 一行，脚本把整棵 Skill 目录拷进仓库，
    > 于是**另一个 agent 在飞的、坏的中间态被一起推上公开仓库** ✗ —— 那一版 `review_surface.py` 在 import 阶段就炸
    >（绝对导入 vs 包路径导入），**生产路径也受影响**，只能另发一次提交回退。
    > 随后建的只读闸门（白名单外 → 退出码 2）**拿这次真实事故做了受控复现**：3 个预期外路径被当场拦下 ✓
    > —— **闸门必须这样反向验一次，否则你不知道它拦不拦得住。**
    > **最容易漏掉的一半（由造成事故的人自己补上的）**：这类闸门**只能比"文件集与内容"，它不可能知道一个被放行的文件此刻正被别的 agent 编辑** ✗。
    > 所以 —— **白名单必须来自"我本来打算改什么"，不能来自"我刚才看到 diff 是什么"**。
    > 后者是循环论证：**你看见 diff 里有不该有的文件，却把它当成"同步的正常产物"收下了** —— 那正是那次事故的思考过程。
    > 判据的写法因此是：**先写下预期路径清单，再跑闸门**；顺序反了，闸门就只是事后追认。

28. **同一个 Skill 目录，同一时刻只允许一个 agent 在写。** 包括"只是同步/推送"的那一个 ——
    **读是共享的，写不是。** 需要并发时，正确做法是**串行化写**（先让编辑方收工，再由一个人统一同步/推送），
    而不是让第二个 agent"只顺手推一下" ✗。
    > 证据：上面那次事故的根因不是脚本，是**调度** —— 同一批目录上同时跑着"编辑"和"同步"两路。
