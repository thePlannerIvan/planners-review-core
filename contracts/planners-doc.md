# planners-doc/2 · 文档契约

工作台只认这一份契约。它规定一份「工作稿」长什么样：文档头怎么声明、页和块怎么分层、块的锚点写在哪里、哪些块算数、什么算出处。内容是 Skill 的事，这份契约不评价判断对不对、来源可不可信。

- 唯一校验器：`scripts/validate-doc.mjs`
- 迁移器：`scripts/migrate-doc.mjs`（`/1` → `/2`，见第 11 节）
- 权威样例：[`contracts/examples/storyline.md`](examples/storyline.md)、[`contracts/examples/by-page.md`](examples/by-page.md)
- 术语以 `GLOSSARY.md` 为准（文档 / 章节 / 页 / 块 / 锚点 / 块 raw / 来源）。

## 1. 文档头

文档的第一行必须是 `---`，紧接着是三个字段，再用 `---` 收口：

```md
---
contract: planners-doc/2
doc: storyline
project: 朗标笔试案
---

# 一、判断
```

| 字段 | 必填 | 值 |
|---|---|---|
| `contract` | 是 | 固定为 `planners-doc/2` |
| `doc` | 是 | `storyline`（梳理主线）或 `by-page`（逐页文案） |
| `project` | 是 | 项目名，非空。**它就是文档名**：工作台用它显示「这是哪份稿」 |

- 只接受 `key: value`；没有文档头、没闭合、字段重复都是错误。
- 契约未定义的字段会产生警告，但不阻断：校验器忽略它，工作台也不会依赖它。
- **文档名只从 `project` 出**，正文不再有文档标题这一行：文件头之后的第一行结构就是 `#` 章节。
- 硬切：`/1` 不兼容读取。`contract` 写 `planners-doc/1` 直接报 `contract_version`，不降级解析；
  存量文档用第 11 节的迁移器一次性迁过来。
- 旧项目（JSON 主稿）不迁移、不兼容读取。需要时按本契约重建。

## 2. 层级

| 级别 | 写法 | 是什么 | 能不能带锚点 |
|---|---|---|---|
| 1 | `# 标题` | 章节 | 不能 |
| 2 | `## 标题` | 页，交付时的一屏 | 不能 |
| 3–6 | `###`–`######` | 普通**标题块**，按层级出字号，不参与结构 | 能 |
| — | 段落 / 列表 / 引用 / 表格 / 图片 / 代码 | 块 | 能 |

- 页的身份是「所在章节 + 顺序 + 标题」。页号由顺序决定，**不写进正文**。
- 页与页之间不加分隔符：`##` 本身就是边界。
- 块应当写在某个 `##` 页里。直接挂在 `#` 章节下的块是中间态：校验器报 `block_outside_page`，
  但编辑时保存不拒绝（ADR 0006，见第 7 节）。
- `##` 页必须写在 `#` 章节里（`page_without_chapter`）。
- 章节与页的标题不是块：给 `#` / `##` 标题加锚点会被拒绝（`anchor_on_structure`）。
- `###`–`######` 任意层级都是合法标题块，层级只决定字号，不决定归属；第五、六级不再被拒绝。

## 3. 块

块是文档里可独立编辑、独立移动、独立反馈的最小单位。**一个块 = 一个段落级元素**。只认七种：

| 块类型 | 怎么认 |
|---|---|
| 段落 | 连续的非空行；遇到空行、标题、列表、引用、表格、图片、代码围栏就结束 |
| 标题 | `###`–`######` 一行 |
| 列表项 | 一行 `-` / `*` / `+` / `1.` 开头；紧跟的缩进续行算同一个块 |
| 图片 | 整行只有一个 `![说明](相对路径)`（可带标题） |
| 表格 | 表头行 + 分隔行（`---`），随后是含 `\|` 的行，到空行为止；首尾管道可省 |
| 代码 | 三个反引号或 `~~~` 围栏，围栏内原样属于这个块 |
| 引用 | 连续的 `>` 行 |

拒绝的写法：

- 原始 HTML 块（`<div>`、`<table>`、`<figure>` 等）—— 要排版就用 Markdown；自定义样式另开页面。
- 分隔线（`---`、`***`、`___`）—— 页与块靠空行和标题分隔。
- Setext 标题（`===` 或 `---` 下划线）—— 只用 ATX 的 `#` 写法。
- 嵌套块：列表项里的列表、引用里的列表、带缩进的列表项。

块与块之间用空行分隔。两个连续的非空行属于同一个段落块；想让它们成为两个块，就空一行。

## 4. 锚点

锚点是块的身份，写成行内 HTML 注释，渲染时不可见：

```md
## 品类定义：150ml 植物节律液

本品以 150ml 浓缩形态锚定「调整状态」。<!-- b:7f3a2c -->
- 舍弃 500ml 解渴逻辑，定价 15 元。<!-- b:81c4d0 -->
```

写法：`<!-- b:` + 6–12 位小写十六进制 + ` -->`，例如 `<!-- b:7f3a2c -->`。

位置：

- **段落、标题、列表项、引用**：写在块最后一行末尾，紧贴内容。
- **图片、表格、代码**：单独一行，紧跟在元素下一行。中间不隔空行。

```md
![剂量与场景的竞争空白](assets/positioning-map.svg)
<!-- b:e3d281 -->

| 元素 | 规格 |
|---|---|
| 瓶身 | 150ml |
<!-- b:4c9a10 -->
```

规则：

- 锚点**全局唯一**。重复时后出现的块被拒绝（`anchor_duplicate`），错误里给出首次出现的行号。
- 锚点可以缺失：工作台首次打开时按正文补写。缺锚点的块在补写前用「第 N 块（类型）」指代。
- 锚点只能有一个，且位置必须符合上面的规则；位置不对（`anchor_position`）或孤立成行（`anchor_orphan`）都是错误。
- 写成锚点但格式不对（位数、大小写、缺 `b:`）报 `anchor_format`，不会被当普通段落吞掉。
- 删除锚点等于删除块身份：下次打开按正文重建，旧评论与任务不跟随（ADR 0003）。
- 锚点不进渲染、不进目录、不改变 Markdown 语义。它不是普通注释的通用容器。

## 5. 出处：页末连续的引用

依据、边界、来源统一写成**页末连续的引用**。位置就是语义，不再用小节标题圈一遍。

- **认定**：页内最后一个块是引用，则从它向前连续的一串引用都算出处区；页中段的引用照常显示、不算出处。
- **数据**：出处区里的每一条仍是一个独立的引用块，锚点写在行尾，与其他块同等（可编辑、可反馈、可重排）。
  解析结果里 `page.sources` 就是这一串块（`[]` 表示这页没有出处区），块上带 `inSources` 标记。
- **渲染**（工作台的事，契约只定数据）：默认收起成一条「出处 · N」，整条是点击区；展开后每条按块编辑，组尾一个「＋ 出处」。
- **校验器只硬查这一条位置规则**：条数不设限，没有出处的页合法，缺不缺由 Skill 判断。
- `/1` 的 `#### Sources` 小节不再有特殊语义——它只是一个普通标题块。存量文档用
  `migrate-doc.mjs --sources-to-quote` 把它转成页末引用（第 11 节）。

## 6. 页为空

一页从 `##` 页标题开始，到下一个 `##` 或 `#` 或文件末尾结束。

- 页里**一个块都没有**就是空页（`page_empty`）。空页仍留在目录里（身份是章节 + 顺序 + 标题），
  校验失败；但编辑时保存不拒绝——页被清空是人的中间态（ADR 0006）。
- 标题块本身是块，所以只有小节标题、没有正文的页不算空页；内容够不够不归校验器管。
- 页标题不能为空（`heading_empty`）。
- 只有引用的页不算空页；页里全是引用时，它们整体构成出处区（第 5 节），不另作评价。

## 7. 重排：移块与移页

位置变化走**显式的重排操作**，不是靠改内容绕过去：`applyBlockContent` 只换一块的内容，
块类型、块顺序、所属页都不许变，也不增删块（增删只走第 8 节的分块 / 合并）；
顺序只能由工作台的 `POST /api/reorder` 改变。

- **移块**：按锚点找到要移动的块，插到目标页的「某块之前」；`before: null` 表示该页末尾。
  跨页移动时块的身份（锚点）与 raw 都不变，章节归属跟着目标页。
- **移页**：整页（`##` 标题连同其下所有块）移到另一页之前 / 之后；页所属章节由落点决定，
  落在某章的两页之间就归那一章。页号不写进正文，重排后按新顺序重新数。
- 块也可以搬到**页外**（章节标题下）：`to: {chapter, outside: true}`。页外块仍然有块身份，
  可以再拖回任一页；它只是暂时不归属任何页。
- 一次只做一个动作，带 `base_sha256`。整份基线过期**不拒绝**：自动重读当前全文、把这次移动重放
  到新版本上；只有锚点已不存在、目标页 / 落点已经没了才停下说明是哪一块
  （`block_missing` / `page_missing` / `reorder_target`）。
- **编辑时不拦越界**：把页里最后一块移走、把章节里最后一页移走都照样落盘。
  页变空、块落到页外不在这里判，由快照提示、由交付校验器判定（ADR 0006）。
- 重排只挪位置：未参与重排的块 raw 逐字保留；候选全文结构不合法不算失败。
- 锁定（模型正在改）与待核对的块不可编辑，因此也不可被移动：移块拒绝被占住的块，
  移页拒绝页内还有被占住块的页，错误码都是 `block_locked`；裁决或解锁后同一动作可以再做。

## 8. 分块、合并与删除：块数量只由这些显式操作改变

`applyBlockContent` 只换一块的内容，不增删块；「回车分块、删空合并」（SPEC 第 4 节）与
「删空即消失」（第 8.1 节）都会改变块数量，所以各有显式命令。它们都按锚点 / 页 / 章定位、
带 `base_sha256` 与可选的 `base_block_sha256`、先拒锁定 / 待核对的块，写盘走同一个 journal；
只重解析验证**这次操作本身**（块身份、数量、位置），不跑校验器（ADR 0006）。

- **回车分块** `POST /api/block/split`：`{anchor, before, after, keep?, base_sha256, base_block_sha256?}`。
  `before` / `after` 是**块内行内 Markdown**（不含 `- ` / `> ` / `### ` 这些块前缀），前缀由服务端按原块类型补；
  标题拆开后，后半退成正文段落，列表项与引用保持同类。新块紧跟原块，拿一个全新的锚点。
  `keep: "before"`（默认）原锚点留在前半；`keep: "after"` 原锚点跟着原来的内容留在后半（块首回车）。
  两半都不能为空：空块没有内容可贴锚点。
- **删空合并** `POST /api/block/merge`：`{anchor, previous, content, base_sha256, base_block_sha256?}`。
  只接受已清空的块（`content` 只剩空白 / 换行）；还有内容的块不能靠合并静默丢掉。
  前一块的锚点与 raw 逐字不动，后一块连同锚点删除。**块身份不迁移**：评论与任务留在原锚点上，
  旧任务 claim 时返回 `task_stale`，不会悄悄改到前一块。
- 一次只做一个动作；合并把页里最后一块并掉、让页变空不拒绝（ADR 0006）。
- 整份基线过期时自动重读、把这次分块 / 合并重放到新版本上；带的 `base_block_sha256` 与当前
  块对不上才停下问人（`block_conflict`）。
- 同一块上两个人撞车同理：后保存的一方拿到磁盘版与自己那一版，两版都进待核对队列（落盘，
  刷新还在），由人并排选一版落盘——不预先拒写，也不静默丢编辑（见 `planners-doc-task/1` 第 4 节）。

### 8.1 删空即消失

删除不是另一类按钮，是「把内容删空、失焦」这一个手势的直接后果。页面负责感知这个手势，
落盘走已有的 `POST /api/structure` 通道（与改名、加页同一个 `structure` 动作名，不新增路由），
并新增三个结构动作：

- **块**：内容被删空、失焦 → `POST /api/structure` 的 `delete-block`（`{anchor, base_sha256}`），
  这一块连同它的锚点从文件里消失。表格不算：清空一个单元格不是删掉整张表。
- **页标题**：文字被删空、失焦 → `delete-page`（`{chapter, index, base_sha256}`），这一页消失。
- **章节标题**：文字被删空、失焦 → `delete-chapter`（`{chapter, base_sha256}`），这一章消失。

页消失时，页里的块按下面的顺序安置，**一条都不丢**（块身份与 raw 逐字不动，所以挂在上面的
批注跟着走）：

1. 并入**同一章内的上一页**；
2. 本章第一页 → 并入**下一章的第一页**；
3. 前后都没有 → 留在原处成为**页外块**（结构不完整是允许的，交给模型收拾；这是唯一允许
   新增 `block_outside_page` 的删除）。

章节消失时，它的页并入**上一章**；第一章则整段并入**下一章**（成为它的前几页）。只有一章的
文档没有邻章可并，页留在顶层。章里唯一一页被删、章因此空了时，章标题跟着消失。

删除同样走 journal 与历史（第 11 节的 `planners-doc-history/1`）：每一次删除写盘前都把上一版
整份存档，删错了用 `POST /api/history/restore` 原样恢复。基线过期照旧自动重读、把删除重放到
新版本上（不返回 409）；要删的块被锁 / 待核对时先拒（`block_locked`）。

## 8.2 造结构之后的空页

`# ` / `## ` 由行首前缀造出结构时，原来那一页可能一块都不剩（在页的第一个块上造章就是这种
情况）。这一页在同一次写入里跟着消失，不让人看到中间那个空页；它挂了批注也照常按块身份走
（块没了就进 `orphan_notes`，见 `planners-doc-diff/1`）。

## 9. 图片

- 图只以文件形式进入文档：`![说明](相对路径)`，位图或 SVG 都行。
- 相对路径**相对文档文件所在目录**解析；文件必须存在、必须是文件（`image_missing` / `image_not_file`）。
- 不接受绝对路径、`http(s)://`、`data:` 等非文件引用（`image_not_relative`）。
- 图片出现在段落、列表项、标题、引用、表格里时同样校验；代码块里的文字不当图片。
- 工作台就地显示、点击放大；取不到图时标「未能加载」，不编造。
- 图块与文字块同等：可反馈、可锁定；锁定的图块不可换文件。换文件只换字节，正文引用路径不变。
- 文档引用的图登记在同名资产清单（`storyline.md` → `storyline.assets.json`），契约见
  [`doc-assets/1`](doc-assets.md)。清单是正文的派生索引，不参与决定用哪张图。

## 10. 校验器

```bash
node scripts/validate-doc.mjs <storyline.md|by-page.md>          # JSON 回执
node scripts/validate-doc.mjs <storyline.md|by-page.md> --text  # 人读输出
```

退出码：

| 码 | 含义 |
|---|---|
| `0` | 合规（可以有警告） |
| `1` | 不合规：至少一个错误 |
| `2` | 用法错误：没给路径、文件不存在 |

JSON 回执：

```json
{
  "contract": "planners-doc/2",
  "valid": false,
  "errors": [
    {
      "code": "anchor_duplicate",
      "message": "锚点 b:aaaaaa 与第 9 行重复；锚点必须全局唯一",
      "line": 11,
      "page": "章节「一、判断」第 1 页「品类机会」",
      "block": "b:aaaaaa"
    }
  ],
  "warnings": [],
  "checked": {
    "path": "/path/to/storyline.md",
    "contract": "planners-doc/2",
    "doc": "storyline",
    "project": "朗标笔试案",
    "chapters": 3,
    "pages": 8,
    "blocks": 40,
    "anchors": 40,
    "sources": 11
  }
}
```

每个错误都带 `line` 与块身份 `block`：有锚点就是锚点本身，没有锚点就是「第 N 块（类型）」；页级错误用「页「标题」」。`page` 说明它在哪一章哪一页。`checked.sources` 是各页出处区的块数合计（第 5 节）。

错误码：

| 码 | 什么时候 |
|---|---|
| `front_matter_missing` / `front_matter_unclosed` / `front_matter_syntax` / `front_matter_duplicate` | 文档头形状不对 |
| `contract_version` | `contract` 不是 `planners-doc/2`（`/1` 不降级读取） |
| `doc_kind` | `doc` 不是 `storyline` / `by-page` |
| `project_required` | `project` 为空 |
| `heading_empty` / `heading_syntax` | 标题为空，或用 Setext 下划线写法 |
| `page_without_chapter` / `block_outside_page` | 结构放错层：`##` 页不在 `#` 章节里，或块不在 `##` 页里 |
| `block_type` / `block_nested` | 七种块之外的块，或嵌套块 |
| `anchor_duplicate` / `anchor_position` / `anchor_orphan` / `anchor_on_structure` / `anchor_format` | 锚点问题 |
| `image_missing` / `image_not_file` / `image_not_relative` | 图片问题 |
| `page_empty` | 页里一个块都没有 |
| `code_unclosed` | 代码围栏没有闭合 |

警告不阻断：`front_matter_unknown`（契约未定义的头字段）、`document_without_pages`（整份文档没有页）。

## 11. 迁移：`/1` → `/2`

```bash
node scripts/migrate-doc.mjs 1 2 <file.md>                      # 就地迁移
node scripts/migrate-doc.mjs 1 2 <file.md> --sources-to-quote    # 顺带把页末 Sources 小节转成引用
node scripts/migrate-doc.mjs 1 2 <file.md> --dry-run             # 只打印结果，不写盘
```

- 每级标题上移一位：`#`（文档标题）移除、`##`→`#`、`###`→`##`，依此类推，`######`→`#####`。
  文档标题的文字只在 `project` 缺失时用来补文档名，不写进正文。
- **块锚点一个不动**；非标题块的 raw 逐字不动，标题块只换行首井号的个数。
- `--sources-to-quote` 是可选的一步：把页末「依据与边界 / Sources」小节的标题删掉、条目逐条转成引用，
  条目文字与锚点不动（列表项的 `- ` 换成 `> `）。出处区前面紧挨着引用块时会给出警告：转完它们会连成一串。
- 迁移完跑一次校验，错误列在回执里但**不阻断**写盘——越界由模型在取稿时补（第 10 节）。
  退出码：`0` 已迁移、`1` 这份文件不是 `/1`、`2` 用法错误。

## 12. 它不做什么

- 不评价内容：判断、结构顺序、来源质量都不看。
- 不检查出处够不够、有几条：只按位置认定出处区（第 5 节）。
- 不检查表格列数是否对齐（Markdown 渲染器会容忍）；超出子集的表格由工作台退化为原文显示，不静默改写。
- 不检查锚点是否由工作台生成、格式是否「好看」；只看写法、位置、唯一性。
- **不在保存路径上跑**：编辑器永远不调用它，结构不合规也照样落盘；它是**交付门禁**——
  Skill 的交付步骤与 CI 必须显式调用它。文件被模型直接改过之后，仍应先跑这个校验器再重建工作台。
- 不为旧 JSON 主稿提供迁移或兼容。
